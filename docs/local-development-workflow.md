# 本地开发与发布流程

源码、界面资源和构建脚本位于本仓库，当前运行目录使用 `artifacts/local-current`。模型、原生依赖、运行时、实际关单和识别历史不提交到 Git。

## 准备和日常迭代

从完整 v0.1.0 便携包运行 `scripts/bootstrap-from-release.ps1 -PackageRoot <目录>`。安装 .NET 8 SDK 后构建主程序，执行核心回归。将完整便携目录复制到 `artifacts/local-current` 后，使用 `scripts/sync-local.ps1` 进行日常增量同步。

同步脚本运行核心业务回归、编译、UI 契约和启动器构建，仅更新运行目录中的程序和文档，清除该运行目录过期版本说明，不重复生成 ZIP。

## 正式发布

统一主程序与启动器版本，编写对应 `docs/release-notes-v<版本>.md`，运行适当的回归、样本对照和干净解压冒烟测试，再用 `scripts/package-release.ps1` 打包。发布包必须带 `SHA256SUMS.txt`，不含真实关单、日志、历史和用户配置。

Windows CI 在核心回归、主程序构建、UI 契约、OCR 自检、受控网页截图、导出及打包门禁成功后发布同一份验证包。后续版本通过工作流手动发布。初始 v0.1.0 发布包已在本地完成验证，并作为本仓库独立重建所需的依赖来源。发布工作流只创建新版本，不删除已有 Release 或标签。

## 版本追溯

本仓库以 v0.1.0 完整源码快照作为初始提交。后续改动通过 Git 提交追溯；旧仓库历史另行本地归档。CI 从本仓库 v0.1.0 Release 准备依赖，不依赖旧仓库或旧发布资产。
