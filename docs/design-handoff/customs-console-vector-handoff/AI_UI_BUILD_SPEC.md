# 关单核验台 AI 制作统一规格

版本：`2.2.0`  
参考画布：`1586 × 992 px`  
目标平台：Windows 10 / 11 桌面客户端  
设计定位：企业级关单识别、核验与数据工作台

> 将本文件连同交付包中的 `assets/`、`design/`、`prototype/` 一并提供给编码 AI。本文件是尺寸、布局、组件和交互的最高优先级真源；出现冲突时依次采用：本文件 → `design-tokens.json` → 主界面 SVG → HTML 原型。

## 1. 给编码 AI 的直接任务

实现“关单核验台”Windows 桌面客户端。主界面只突出关单统计与关单记录，不添加宣传语、欢迎区、侧边导航或与业务无关的内容。

必须完整实现：

1. 软件名称与软件图标只展示，不可点击。
2. 目录设置弹窗，可分别设置关单读取目录和截图保存目录。
3. 关单清理、截图清理、列表清理均有独立二次确认。
4. 开始识别前校验目录，识别任务异步运行。
5. 统计本批关单数、重复单号数、去重前总价、去重后总价。
6. 单号搜索、记录筛选、每页数量、分页和固定行高表格。
7. 直接使用交付包中的软件图标与五枚专用按钮 SVG，不自行替换或拼接图标。

禁止：

- 不得把界面改成网页后台、营销首页或大圆角卡片仪表盘。
- 不得恢复深蓝色大面积表头、彩色卡片左边条、厚重阴影或装饰性渐变背景。
- 不得在空列表文案下增加说明文字。
- 不得让表头竖向分割线延伸到空白表格内容区。
- 不得使用通用垃圾桶、播放键或多个通用图形临时拼成主操作图标。

## 8. 按钮与图标统一规范

### 8.1 主界面按钮骨架

| 参数 | 值 |
| --- | --- |
| 高度 | `44px` |
| 圆角 | `7px` |
| 边框 | `1px` |

把“图标 + 10px 间距 + 文字”视为一个完整内容组，使用 Flex/Grid 在按钮中水平和垂直双向居中。不得依赖文本 baseline 对齐图标。

### 8.2 专用图标映射

| 按钮 | 资源 | 具体造型 |
| --- | --- | --- |
| 目录设置 | `directory-settings.svg` | 文件夹内部整合两组路径调节器 |
| 关单清理 | `declaration-clean.svg` | 带折角的关单文件与删除标记 |
| 截图清理 | `screenshot-clean.svg` | 图片缩略图、山形内容与删除标记 |

| 列表清理 | `list-clean.svg` | 三行记录列表与清除标记 |

SVG 使用 `currentColor`，由按钮状态决定颜色。不要修改图标内部路径，不要在外部再叠加垃圾桶、齿轮、播放键或角标。

### 8.3 按钮状态

- Hover：只调整容器颜色一个层级，不移动控件。
- Pressed：亮度约 `0.96`，不得缩放导致布局跳动。
- Focus：`2px #315C9D` 外轮廓，偏移 `2px`。
- Disabled：透明度 `0.42`，不可点击。
- Loading：保留原按钮宽度，文字改为“识别中…”并显示进度图标；禁止重复提交。

## 14. 识别流程与状态

```text
idle → validating → scanning → verifying → completed
                   ↘ error ↗
```

- `idle`：按钮显示“开始识别”。
- `validating`：检查关单目录存在且可读、截图目录存在且可写。
- `scanning`：后台读取图片/PDF并执行 OCR；按钮显示“识别中…”。
- `verifying`：检测重复单号、执行核验、保存截图。
- `completed`：刷新统计与列表，显示成功提示。
- `error`：保留已成功记录，给出具体错误和重试入口。

每识别出一条记录即可增量加入表格，不要等待整个批次结束后一次性显示。长任务必须在后台线程或异步任务中运行，不得阻塞 UI。

## 15. 搜索、筛选与分页

- 搜索仅针对报关单编号，建议 `200ms` 防抖。
- 搜索、筛选和页数变化后重新计算结果数与页数。
- 刷新数据时保留当前搜索、筛选和每页数量。
- 当前页超出新结果页数时跳转到最后有效页。
- 表格行始终为 `56px`，不得因换行或内容高度变化而扩张。

## 16. 文件清理安全规则

1. 目录清理执行前重新解析规范化绝对路径。
2. 拒绝空路径、磁盘根目录、用户主目录、应用目录及它们的上级目录。
3. 验证目标目录类型和访问权限。
4. 默认优先移动到回收站。
5. 清理期间禁用对应按钮，防止重复提交。
6. 失败时显示具体错误，不修改未成功处理的文件状态。
7. “列表清理”不得调用任何文件删除接口。

## 17. 推荐架构边界

```text
UI / ViewModel
├── SettingsService
├── FileSystemService
├── RecognitionService
│   ├── OcrAdapter
│   ├── DuplicateChecker
│   └── VerificationAdapter
├── ScreenshotService
└── RecordRepository
```

UI 只负责状态展示和命令触发，不直接删除文件，也不直接调用 OCR SDK。所有长任务使用取消令牌或等效机制，服务层返回结构化错误码和用户可读信息。

## 18. 可访问性与桌面交互

- 所有点击目标至少 `44 × 44px`。
- 普通文字对比度不低于 `4.5:1`；非文字边界和焦点不低于 `3:1`。
- 所有控件支持键盘焦点，焦点顺序与视觉顺序一致。
- 弹窗打开后焦点限制在弹窗内，Escape 关闭非强制弹窗。
- 危险确认的默认焦点放在“取消”，不要放在“确认清理”。
- 图标按钮必须提供可访问名称；装饰性图标设置为不可读。
- Windows 高 DPI 下使用逻辑像素和矢量图标，不使用低分辨率位图放大。
